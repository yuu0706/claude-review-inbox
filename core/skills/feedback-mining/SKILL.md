# 指摘の取りこぼし探し

一度受けた指摘を次から反映し、同じ指摘を二度させないための仕組みである。

指摘は本来、会話の中でその場で決まり（CLAUDE.md・スキル・メモリ）へ反映する。本スキルは、その場で反映し忘れた指摘を拾う役である。
「2.」の「決まりがあるのに守れていない指摘」に加え、会話の中で反映したはずの指摘が、反映の後にもう一度出ていないかも確かめる。Skill `skill-audit` の変更の記録（`${SKILL_AUDIT_STATE:-~/.local/state/skill-audit}/history.md`）があれば、その日付と突き合わせる。

利用者の環境だけの決まり（呼び名・CLAUDE.md の節名・検索する場所の追加など）は、上書きファイル `${XDG_CONFIG_HOME:-~/.config}/claude-skills/feedback-mining.local.md` に書く。あれば最初に読み、本文と食い違う箇所は上書きファイルに従う。

## 0. 範囲

- 自動モードで書いてよいのは、依頼文に書かれた結果の出力先だけである。CLAUDE.md・スキル・メモリは直さない。
  `scripts/run.sh` が権限の設定で強制する。拒否された操作を別の方法で行おうとしてはならない。
- 対象の会話は、前回の実行より後に更新された会話だけである（`run.sh` が選ぶ）。自動実行のセッションは除いてある。
- 自動モードでは、元の会話の履歴（jsonl）を読まない。`run.sh` が利用者本人の発言だけを取り出したファイル（`scripts/extract-user.py`。ツールの結果・フックの出力・スラッシュコマンドの展開・貼り付けた文章の中身を除いたもの）を作り、その一覧を依頼文で渡す。jsonl の読み取りは権限で拒否している。取り出したファイルの見出しにある元の会話のパスを、根拠として書く。
- 承認待ちの置き場所（`~/claude-reports/proposals/`）と判断の台帳（`~/.local/state/claude-review-inbox/`）・変更の台帳（`~/.local/state/claude-change-ledger`）には書き込めない（`run.sh` が権限で拒否する）。
- 決まりの案は、承認の進め方（承認あり・承認なし）によらず、常に承認待ちにする（Skill `change-review` の「0.2」）。

## 1. 手順（自動モード）

1. 上書きファイルがあれば読む。続けて依頼文の一覧にある取り出したファイルを読み、利用者の発言から、Claude の振る舞いを直した指摘を拾う（会話の中で依頼されたときは、jsonl のうち `type` が `user` で、ツールの結果・フックの出力・貼り付けた文章ではない部分だけを読む）。
   - 例: 「違う」「そうじゃない」「さっきも言った」「〜しないで」「〜してって言ったよね」、作業の差し戻し、やり直しの依頼。
   - 業務の内容そのものへの指示（仕様の変更など）は指摘ではない。振る舞い（進め方・確認の仕方・書き方・道具の使い方）への指摘だけを拾う。
2. 指摘ごとに、すでに反映されているかを確かめる。
   - 各設定ディレクトリ（既定は `~/.claude`。2つ目の設定ディレクトリがあれば、それも含む）の `CLAUDE.md`・`skills/*/SKILL.md`・`projects/*/memory/` を検索する。
   - 同じ趣旨の決まりがあれば「反映済み」とし、決まりがあるのに同じ指摘をされていれば「決まりがあるのに守れていない」とする。
3. 否認リスト（`~/claude-reports/proposals/rejections.md`。自動のときは依頼文に書かれたパス）を読む。利用者が却下した変更の一覧である。
4. 反映されていない指摘と、守れていない指摘について、決まりの案を作る。
   - **否認リストと同じ対象・同じ趣旨の案は作らない。** 却下された理由（メモ）を覆す新しい根拠がある場合も案にせず、結果の「4.」の後に「否認リストと重なるため案にしなかった指摘」として番号と否認リストの ID を書く。
   - 案ごとに、入れる先（CLAUDE.md のどの節・どのスキル・メモリ）と、書く文面を示す。
   - 文面は、入れる先の既存の書き方に合わせる。
5. 結果を、依頼文に書かれた出力先へ書く。構成は「2.」のとおり。

## 2. 結果の構成

1. 作成日時、対象の会話の数、対象の期間
2. 決まりの案（番号・指摘の要約・根拠の会話のファイルと日時・入れる先・文面）
3. 決まりがあるのに守れていない指摘（番号・既存の決まりの場所・根拠の会話・守れなかった原因の推測）。推測は推測と書く
4. 反映済みだった指摘の件数

利用者の発言を引用するときは、必要な部分だけにする。結果は業務文書として書き、口調・絵文字を使わない。

## 3. 結果を読む依頼への対応

1. Skill `report-inbox` の手順で結果を開く。
2. 決まりの案を、Skill `change-review` の承認待ちとして `~/claude-reports/proposals/` に1件ずつ出す。反映先が CLAUDE.md・スキル・メモリのどれでも同じ扱いとする。
   出す前に否認リスト（`~/claude-reports/proposals/rejections.md`）を読み、同じ対象・同じ趣旨の案は出さない（`change-review` の「案を出す側が守ること」）。
   根拠が弱い案（1回だけの発言から作った案、推測で原因を書いた案）は承認待ちにせず、結果を伝えるときに「保留」として理由と一緒に示す。
3. 利用者の承認を受けたものだけを、`change-review` の「4.2 会話での反映」の手順で反映する。
4. 伝え終えたら、`report-inbox` の手順で既読にする。
